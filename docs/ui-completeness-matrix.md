## Implementation rule

Every `MISSING` and `PARTIAL` entry will be converted to a route that uses shared HOBEE UI primitives, visible loading/empty/error/success/permission states and centrally-defined presentation contracts. Presentation data will never be represented as verified revenue, payment, balance or provider result.

## UI COMPLETE FIRST — Final Status

> **This section supersedes the earlier baseline labels above.** The baseline is retained as an audit record of the original gaps. The current result below reflects the completed UI COMPLETE FIRST implementation, without changing Supabase schema, authentication, order/payment, loyalty, or Vercel API contracts.

The project now supplies a navigable presentation workspace for every requested operating role. Each workspace uses a centralized role contract, shared HOBEE components, explicit presentation boundaries, and an available deep-link fallback. Where real data is unavailable, the UI reports the integration boundary or renders a purpose-built empty state; it does not present financial, order, or operational figures as verified data.

## Navigation, Safe Area, and State Controls

Every specialised role hub uses `ScreenContainer` with top, left, right, and bottom safe-area edges. Role hubs, Support Center, and Notification Detail now use `goBackOr()` so normal navigation history is retained while direct/deep-link entry returns to a deterministic, non-dead-end destination.

| Route family | Fallback when no history is present | State behaviour |
|---|---|---|
| Role hubs and generic role workspace | `/my-hobee` | Navigation-card route entry, loading/empty presentation contract, safe back behaviour |
| Support Center | `/(tabs)/account` | Topic routing and explicit unavailable-contact integration boundary |
| Notification Detail | `/my-hobee/notifications` | Loading, retry, not-found/global-error surface, mark-as-read, controlled action route |
| Admin workspaces | Admin Portal shell | Admin permission gate, loading, protected presentation boundary, existing portal navigation |

## Remaining External Gates

The UI phase does not remove production integration gates. The owner must still reconnect the Vercel team that owns the deployment, set server-only variables there, and provide controlled environments for Opn sandbox, push delivery, carrier integration, and real-device iOS/Android testing. These dependencies are deliberately reported as integration boundaries rather than hidden behind synthetic operational data.
